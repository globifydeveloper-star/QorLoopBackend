# Architecture Decision Record (ADR) 002: ORM Selection

- **Status:** Approved
- **Date:** 2026-10-26
- **Context:** Database Data Access Layer
- **Options Evaluated:** Prisma vs. Drizzle ORM

## Context & Requirements
1. PostgreSQL 16 database.
2. Tenant-ready data model: `tenant_id` on all customer tables, composite unique indexes (e.g. `(tenant_id, normalized_barcode)`), and strict tenant-scoped queries.
3. High-volume bulk inserts/upserts (e.g., 50,000 products/listings applied within transactions).
4. Predictable, transparent SQL with zero runtime query engine overhead.

## Decision
We select **Drizzle ORM** with `drizzle-kit` and `postgres.js`.

## Rationale
- **Zero Binary Engine Overhead:** Prisma requires an internal Rust query engine binary, introducing binary cold-start latency, memory overhead, and connection management friction in small container instances. Drizzle is pure TypeScript with zero overhead.
- **Bulk Performance:** Drizzle compiles directly to native SQL `INSERT INTO ... ON CONFLICT (...) DO UPDATE` statements, processing batch operations an order of magnitude faster than Prisma.
- **Composite Unique Index Support:** Drizzle gives full first-class declarative control over compound indexes and schema definitions across PostgreSQL domains.
- **Migration Control:** `drizzle-kit` produces clean, inspectable SQL migration files without hidden schema magic.

## Consequences
- Schema is centralized in TypeScript files under `src/db/schema/`.
- Queries utilize the Drizzle query builder or relational API with mandatory `eq(table.tenantId, tenantId)` scoping.
